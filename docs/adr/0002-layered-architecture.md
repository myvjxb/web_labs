# ADR 0002: Шарова архітектура застосунку

* **Статус:** Прийнято
* **Дата:** 2026-11-25

## Рішення
Код бекенду організовано у 3 шари з напрямком залежностей зверху вниз (`api/ → service/ → domain/`):
* **`api/`** — Express-роути та контролери: приймають HTTP-запити, передають дані в `service/` і повертають DTO-відповіді за контрактом.
* **`service/`** — бізнес-логіка (use-cases), валідація вхідних даних, мапінг `DTO ↔ domain`, робота зі сховищем даних.
* **`domain/`** — доменні сутності (`Product`, `User`, `Order`) та їхні інваріанти без залежності від Express чи БД.

## Заборонені зв'язки
* `api/` не звертається напряму до БД або доменних сутностей в обхід `service/`.
* `domain/` не імпортує нічого з `api/` чи `service/`.

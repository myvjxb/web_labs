# Бізнес-документ: Music Store

## 1. Назва та короткий опис системи
**Music Store** — це веб-застосунок інтернет-магазину музичних інструментів та аксесуарів (електрогітари, комбопідсилювачі, струни, педалі ефектів тощо). Система дозволяє покупцям зручно переглядати каталог товарів, шукати потрібне обладнання та оформлювати замовлення онлайн.

Проєкт реалізується як клієнт-серверний веб-застосунок (HTML/JS фронтенд + Node.js/Express бекенд + база даних SQLite/PostgreSQL). Архітектура проєкту закладає можливість поступового розширення: від простого каталогу до повноцінного CRUD, авторизації, обробки замовлень та контейнеризації.

## 2. Користувачі системи (Ролі)
* **Гість (Неавторизований користувач)** — може переглядати каталог товарів та деталі окремих позицій.
* **Покупець (Авторизований користувач)** — може додавати товари в кошик, оформлювати замовлення та переглядати їх історію.
* **Адміністратор (Менеджер магазину)** — може додавати нові товари, редагувати ціни/описи, видаляти позиції та керувати статусами замовлень.

## 3. Основні сценарії використання (Use Cases)
1. **Перегляд каталогу товарів:** користувач відкриває головну сторінку, система робить запит до API і відображає актуальний список музичних інструментів.
2. **Перегляд деталей товару:** користувач обирає конкретний інструмент, щоб побачити його характеристики, ціну та наявність.
3. **Управління каталогом (Адмін):** адміністратор додає новий товар, оновлює ціну існуючого або видаляє неактуальну позицію.
4. **Оформлення замовлення:** покупець формує замовлення з обраних товарів, система фіксує його в БД та повертає підтвердження.

## 4. Функціональні вимоги
* Відображення списку товарів із бази даних через REST API (`GET /items`).
* Створення, оновлення та видалення товарів (повний CRUD).
* Валідація вхідних даних та повернення зрозумілих помилок у єдиному форматі.
* Реєстрація та базова авторизація користувачів (у майбутніх ітераціях).
* Оформлення та збереження замовлень з підтримкою ідемпотентності.

## 5. Нефункціональні вимоги
* **Швидкодія:** час відповіді API на базові запити (перегляд каталогу) не повинен перевищувати 300–500 мс.
* **Надійність:** коректна обробка помилок, таймаутів та повторних запитів (retries, rate-limiting).
* **Зручність (Usability):** зрозумілий мінімалістичний інтерфейс, коректна робота у сучасних браузерах.
* **Масштабованість та переносимість:** можливість запуску сервісів у Docker-контейнерах на будь-якому середовищі.

## 6. Обмеження (Що система точно НЕ буде робити)
* Система **не** реалізує реальний еквайринг (списання коштів з банківських карток) — оплата лише імітується або фіксується як статус.
* Система **не** має інтеграції з реальними службами доставки (Нова Пошта, Укрпошта тощо).
* Система **не** передбачає окремих нативних мобільних застосунків (iOS/Android) — лише веб-версія.
* Система **не** підтримує мультивалютність та автоматичну конвертацію курсів.
